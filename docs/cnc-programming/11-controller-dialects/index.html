Controller Dialects

G-code is not universal. FANUC, Siemens, Heidenhain, and Haas share the same concepts — coordinates, motion, cycles, offsets — but differ in syntax, cycle format, parameter meaning, and even which G-code number does what. Always program for your actual controller.

Concept

CNC programming has a common core: Cartesian coordinates, G00/G01 motion, work offsets, tool offsets, and canned cycles. But the words and numbers used to express that core vary by controller — just like two natural languages both express the same idea but use different vocabulary. A program written for a Haas mill may alarm on a Siemens machine, and vice versa. This page uses Haas (FANUC-compatible) syntax as the reference dialect and points out where other controllers differ.

Why It Matters

A programmer who knows one controller can usually read another, but writing directly for an unfamiliar one without checking the manual causes alarms, broken tools, and scrapped parts. The differences are not cosmetic: the same G81 drilling cycle on one control retracts to a different plane, and the same G76 thread cycle uses completely different parameter words. Copying code from the internet or a textbook without checking the dialect is a leading cause of first-part crashes.

How It Works

The Major Controllers

  • FANUC: the most common global control. Standard G81/G83 drilling cycles, G94/G95 feed modes, M98 P calls for subprograms, two-line G76 thread cycle, #1/#2 macro variables.
  • Haas: simplified and FANUC-compatible. One-line G76 with K/D, G99 for feed-per-rev on lathes, M98 P calls. Uses the same G80/G81/G83 cycle family.
  • Siemens (Sinumerik): uses named cycle calls (CYCLE82, CYCLE83) instead of G81/G83, R parameters, and a different offset system. Program structure uses channel and syntax blocks.
  • Heidenhain: conversational-style programming with Q parameters, straight-line and circular touch-screen blocks, and its own cycle vocabulary.

Program Structure Differences

A FANUC/Haas program starts with O0001 and ends with M30. A Siemens program uses a program name and a different end marker. Heidenhain programs are often entered conversationally on the control rather than transferred as text. Work offsets: FANUC/Haas uses G54–G59; Siemens uses a different offset frame; Heidenhain uses a datum table. The concept is the same — a work origin offset from machine zero — but the number and method differ.

M-Codes Are Machine-Specific

Even on FANUC-compatible controls, M-codes vary by machine builder. M03/M04/M05 and M08/M09 are near-universal, but tool change, chuck clamp, tailstock, and pallet M-codes differ. A Mazak lathe may use different M-codes than a Haas lathe for the same physical action. Never assume an M-code from one machine works on another.

FANUC in Detail

FANUC controls are found on machines worldwide, from Tsugami to Makino. The program starts with Oxxxx and uses G80–G89 cycles. Subprograms are called with M98 Pnnnn (call O nnnn) and returned with M99. Macro variables are #1–#33 (local) and #100–#199 (common). Threading uses the two-line G76 with P and Q words. FANUC is the baseline that most other controls are compared against.

Haas in Detail

Haas controls are FANUC-compatible but simplified. On lathes, G99 (instead of G95) sets feed per revolution. The thread cycle is one-line G76 with K (thread height) and D (first pass depth). Canned cycles use the same G80–G83 family. Haas uses M98 P calls for subprograms. The main difference from FANUC is simplification: fewer parameters, more defaults, and a touchscreen interface. Programs written for a Haas mill usually run on a FANUC mill, but always check.

Siemens Sinumerik in Detail

Siemens controls (840D, 828D) are common on European and high-end machines. They use named cycles instead of G-codes: CYCLE82 for spot drilling, CYCLE83 for peck, CYCLE84 for tapping. Variables are R1, R2. Work offsets use a frame system. The program structure includes channel definitions and syntax blocks. A program that runs on a FANUC machine will not run directly on a Siemens machine; it must be rewritten using the Siemens cycle calls and parameter list.

Heidenhain in Detail

Heidenhain controls (TNC 640, iTNC 530) are common on mold and die machines. They use conversational programming: the operator fills in a dialog on the screen for each cut, rather than writing text G-code. Q parameters replace # variables. Straight-line and circular blocks are entered as HEIDENHAIN touch points. Heidenhain can also read and run G-code programs, but the native programming style is conversational.

Why This Site Uses Haas

This site uses Haas (FANUC-compatible) syntax as the reference because it is widely taught, well documented, and the programs are portable to most FANUC-compatible mills and lathes. When you move to a Siemens or Heidenhain machine, the concepts — coordinates, offsets, cycles, work planes — are the same; only the words change. Learn the concepts first, then learn the dialect of the machine you are running.

Coordinate System and Direction Conventions

Across controllers, the right-hand coordinate system is the same: X, Y, Z follow the right-hand rule, and rotary axes A, B, C follow the curled-finger direction. Work offset numbers differ (G54 vs frame vs datum table), but the concept — an origin offset from machine zero — is universal. Plane selection G17/G18/G19 is also consistent across FANUC/Haas. On Siemens, plane selection uses a different word but the geometry is the same.

Program Transfer and Post-Processors

In a modern shop, most programs come from CAM software. The post-processor converts the CAM's generic toolpath into the specific dialect of the target machine. A CAM post for a Haas mill outputs G81 cycles; the same CAM post for a Siemens machine outputs CYCLE82. This is why a CAM program does not usually need manual porting — the post handles the dialect. If you write G-code by hand, you must do what the post does automatically: translate geometry into the correct cycle syntax.

Alarm Messages and Diagnosis

When a program alarms, the alarm number and text point to the control dialect. A FANUC alarm like "020 OVER TRAVEL" means something different from a Siemens alarm. Reading the alarm manual for your specific control is the first diagnostic step. Many alarms are not program errors at all: they are setup errors (wrong offset, tool not clamped, door open). The alarm message is the control telling you what it sees, not what you intended.

Learning a New Control

If you already know FANUC/Haas, moving to Siemens or Heidenhain is not learning CNC from scratch. The concepts — coordinates, offsets, cycles, work planes, subprograms — transfer directly. What changes is the vocabulary and the cycle parameter format. Spend a day with the manual for the new control, write a simple test part in air, and run it in single block. Within a week you will be productive; within a month you will be fluent.

Siemens (Sinumerik): the same operation is programmed as a CYCLE82 call with parameters for depth, retract plane, and dwell. The syntax is completely different; the geometry concept (rapid to R plane, feed to depth, retract) is the same.

Heidenhain: entered as a conversational drilling block on the control, with depth and feed filled in on the screen.

Work Offset and Tool Offset Differences

On FANUC/Haas, work offsets are G54–G59 in a table. On Siemens, work offsets are set in a frame (ROT, TRANS) and activated differently. On Heidenhain, the datum table stores work zero. Tool length and radius offsets are stored in offset tables on all controls, but the offset numbering and how they are called (H vs D vs T) differ. The concept — a stored correction between machine position and tool-tip position — is universal; the access method is not.

Canned Cycle Differences

G81 drilling on FANUC/Haas uses R plane, Z depth, F, and G98/G99 retract. On Siemens, CYCLE82 takes parameters for depth, retract plane, dwell, and feed in a single block. The geometry (rapid to R, feed to depth, dwell, retract) is the same, but the parameter order and names are different. A programmer moving between controls must look up the cycle parameter list every time — guessing leads to wrong Z depths or wrong R planes.

Subprogram and Macro Differences

FANUC/Haas subprograms use M98 P calls and M99 returns. Siemens uses procedure calls with parameter passing. Heidenhain uses labels and CALL LBL. Variables: FANUC #1, Siemens R1, Heidenhain Q1. Conditional logic: FANUC uses IF[#1 EQ#2] GOTO, Siemens uses IF, Heidenhain uses FN. The programming concept — parameterized repeated logic — is the same, but the syntax differs enough that a macro written for one control must be ported, not copied.

Practical Porting Checklist

When moving a program from one control to another: (1) check units (G20/G21), (2) check work offset numbering, (3) check tool offset call (H vs D), (4) rewrite canned cycles using the target control's syntax, (5) convert subprogram calls and variables, (6) verify M-codes for chuck, coolant, and tool change, (7) run the program in dry run and single-block before cutting. Never assume a program transfers without changes. Even a simple program with no cycles can fail if the work offset numbering or tool offset call differs. Test in dry run with the tool off the part.

Controller Version Matters

Even within one brand, different versions differ. A FANUC 0i-MF and a FANUC 31i may have slightly different cycle behaviors. A Haas NextGen control and a older Haas have some parameter differences. The manual for the specific control version, not the brand, is the authority. When in doubt, run a simple test move in air before cutting.

Machine Builder Add-Ons

Beyond the control dialect, the machine builder adds its own M-codes and macros for things like chip conveyor, coolant tank level, tool probe, and pallet changer. These are documented in the machine builder manual, not the control manufacturer manual. A Haas VF and a Mazak VMC may both run FANUC controls, but their chip-conveyor M-codes differ. When you move to a new machine, ask the programmer on shift for the "magic M-codes" sheet — it usually has the builder-specific functions written down.

Documentation and Version Control

Because dialects differ by machine and version, keep a paper or digital cheat sheet at each machine with the exact cycle format, M-codes, and offset numbering for that control. When a program is transferred between machines, note the target machine on the program printout. This avoids the common shop-floor problem of running a program on the wrong machine because the paper printout did not say which control it was written for.

The key takeaway: CNC concepts are universal, but syntax is not. Learn the concepts deeply, and treat each new control as a new dialect of the same language rather than a new language. With the manual at hand and a few test cuts in air, any experienced programmer becomes productive on a new control within days. This site uses Haas syntax throughout, but the principles apply to every control, regardless of brand or version.

Common Mistakes

  • Assuming G81 means the same thing on every controller — R plane and retract behavior can differ; verify the cycle definition.
  • Copying G-code from a textbook or the internet without checking the dialect — a program written for a different control may alarm or move unexpectedly.
  • Assuming M-codes are universal — many M-codes are machine-builder-specific, especially chuck, tailstock, and pallet functions.
  • Using # variables on a Siemens machine — Siemens uses R parameters, not # variables.
  • Expecting G76 thread parameters to match across machines — FANUC two-line G76, Haas one-line G76, and Siemens CYCLE97 all use different words.

Practice

1. What does M98 P2000 do on a Haas?

Show answer

Calls subprogram O2000 once. The P-address specifies the program number.

2. Why should you not assume G-code from one machine works on another?

Show answer

Cycle formats, parameter meanings, and even G-code assignments vary by controller and manufacturer. Always verify against the machine's manual.

3. Which controller uses CYCLE82 instead of G81?

Show answer

Siemens Sinumerik. The drilling concept is the same; the syntax is a named cycle call.

4. What variable symbol does Heidenhain use instead of FANUC #1?

Show answer

Q parameters (Q1, Q2). Siemens uses R parameters.
