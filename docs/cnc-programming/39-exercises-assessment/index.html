Exercises & Assessment

Reading and understanding code is the skill that prevents crashes. These 20 exercises test coordinate systems, G-code, offsets, cycles, compensation, and program structure. Work through them without looking at the answers first.

Part 1 — Knowledge Check (Questions 1–12)

  1. What does G01 do, and how is it different from G00?
    Answer

    G01 is linear interpolation at a controlled feed rate F — the tool cuts in a straight line at the programmed feed. G00 is rapid positioning at machine maximum speed, used for non-cutting moves, and does not use F for cutting.

  2. What is G54?
    Answer

    G54 is the first work coordinate system offset (work zero). It shifts the coordinate origin from machine zero to the workpiece datum, so the programmer can use part coordinates instead of machine coordinates.

  3. What is the difference between G90 and G91?
    Answer

    G90 = absolute programming: every coordinate is measured from the work zero. G91 = incremental programming: every coordinate is measured from the current tool position. G90 X50 means "go to X50"; G91 X50 means "move 50 mm in X."

  4. What does G41 do?
    Answer

    G41 activates cutter radius compensation to the left of the programmed direction. The machine offsets the tool center by the radius stored in the D code, so you program the part outline rather than the tool center path.

  5. On a lathe, what does X40 mean?
    Answer

    X40 means the tool is positioned at a 40 mm diameter, not 40 mm radius. The actual radial position is 20 mm from center. Radial depth of cut = (X_start − X_end) / 2.

  6. What does G80 do?
    Answer

    G80 cancels all canned drilling cycles. It stops the modal cycle mode; after G80, subsequent X/Y/Z motion is explicitly controlled by G00/G01 rather than by an active cycle. Note: G80 does not retract Z — write G00 Z50 explicitly. On Haas, a G00 or G01 motion also cancels the cycle, but writing G80 explicitly makes the intent clear.

  7. What is the difference between G98 and G99 in a drilling cycle?
    Answer

    G98 retracts to the initial Z plane (the height before the cycle was called). G99 retracts only to the R plane. Use G99 for holes with no obstructions between them; use G98 when there is a boss, clamp, or feature to clear.

  8. Why program G21 G17 G90 G40 G49 G80 at the start of a program?
    Answer

    To establish a known machine state: G21 = metric units, G17 = XY plane, G90 = absolute programming, G40 = cancel compensation, G49 = cancel tool length offset, G80 = cancel cycles. It prevents inherited modal states from a previous program.

  9. What is the difference between feed per minute (mm/min) and feed per revolution (mm/rev)?
    Answer

    mm/min is how far the tool travels each minute. mm/rev is how far the tool advances per spindle revolution. On the Haas lathe examples in this course, G98 selects feed per minute and G99 selects feed per revolution; on other controllers the code may differ — check the operator manual for the machine in front of you. The conversion is: mm/min = mm/rev × rpm. Example: 0.20 mm/rev at 1000 rpm = 200 mm/min.

  10. What does G43 H01 do?
    Answer

    G43 activates tool length compensation using the H01 offset value. The controller adds (or subtracts, depending on sign convention) the measured tool length from the programmed Z position, so different tools reach the same programmed Z without editing the program.

  11. What is the difference between climb (down) milling and conventional (up) milling?
    Answer

    Climb milling: the cutter rotates in the same direction as table feed; chip starts thick and tapers, usually better finish and longer tool life. Conventional milling: cutter rotates against feed; chip starts thin and rubs, can cause backlash on worn machines.

  12. What is a work offset (fixture offset), and how many are commonly available?
    Answer

    A work offset (G54–G59, plus extended offsets on many controls) stores the X/Y/Z shift from machine zero to a part origin. Multiple offsets let you run several fixtures or setups without changing the program.

Part 2 — Code Reading (Questions 13–16)

9. Trace this program. Where does the tool end up at the end?

G90 G54 G00 X20. Y20.
G43 H01 Z50. M03 S2000
G01 Z-2. F100.
G01 X80. F300.
G00 Z50.
G00 X0 Y0
M30
Trace

1. Rapid to XY (20,20). 2. Spindle on at S2000, rapid to Z50 with tool length offset H01. 3. Feed down to Z−2 at 100 mm/min. 4. Feed to X80 (Y stays at 20) at 300 mm/min. 5. Rapid up to Z50. 6. Rapid to X0 Y0. 7. Program end. Tool ends at X0 Y0 Z50.

10. What does this subprogram call do? How many times does it run?

M98 P2000 L5
Answer (Haas)

P2000 calls subprogram O2000; L5 repeats it five times. If O2000 drills one hole at the current XY, this line calls O2000 five times at the same XY — repeat count alone does not create five different hole positions. The caller must reposition XY before each call to drill at different locations.

11. Read the turning program. What diameter does it end at?

G00 X50. Z2.
G01 Z0 F0.2
X45.
Z-30.
X52.
Trace

Approach at X50 Z2. Feed to Z0. Step to X45 (now cutting Ø45). Turn along Z to Z−30 at Ø45. Step out to X52. The turned diameter is Ø45 over the length Z0 to Z−30.

12. After this line, what mode is the machine in?

G99 G83 R2. Z-15. Q3. F120.
Answer

Peck drilling cycle (G83) is active, modal. Retract mode is G99 (return to R2 after each hole). The cycle stays active until G80 or another documented cancelling motion command (such as G00/G01 on Haas). The next X/Y line will peck-drill at that position.

Part 3 — Find the Error (Questions 17–20)

13. This program has a bug. What happens?

G90 G54 G00 X0 Y0
G43 H01 Z50.
G01 Z-5. F100.
G01 X50.
G41 D05
G01 X80. Y30.
G00 Z50.
M30
Diagnosis

G41 is engaged at Z−5 while already inside material, without a lead-in move from outside the part. There is no G40 at the end to cancel compensation. There is also no startup block (G21, G17, G94, G80, G49). G41 must be engaged on a lead-in move from outside the stock, not mid-cut.

14. On a Haas, after the last hole at (50,50), this program uses G00 Z50. without writing G80. Does the machine continue drilling? How can the exit state be made clearer?

G90 G54 G00 X10. Y10.
G43 H01 Z50. M03 S1500
G81 R2. Z-15. F100.
X50. Y10.
X50. Y50.
G00 Z50.
M30
Diagnosis

On Haas, the G00 Z50 motion itself cancels the G81 cycle — the machine will not continue drilling. However, writing an explicit G80 before the Z retract makes the program's intent unambiguous and protects against controller differences. Best practice: add G80 before G00 Z50. This is a clarity issue, not a crash bug.

15. This turning program cuts the wrong diameter. Why?

G00 X30. Z2.
G01 Z0 F0.2
Z-30.
X40.
Diagnosis

The tool starts at X30 (Ø30 diameter) and turns along Z to Z−30 without changing X — it cuts a Ø30 shaft, not the intended Ø40. If the goal is to turn from Ø50 to Ø40, the X should start at X50 and step to X40 before the Z move.

16. This tapping program will strip the threads. Why? Assume G94 (feed per minute) is active.

G84 R5. Z-15. F500.
(S500, M10x1.5 tap)
Diagnosis

In G94 mode, F must = pitch × RPM. For M10×1.5 at S500, F = 1.5 × 500 = 750 mm/min, not 500. The feed is too slow for the spindle speed, so the tap does not follow the thread pitch and strips the threads. If G95 were active instead, F would be in mm/rev and F1.5 would be correct — always know which feed mode is active.

What This Assessment Does and Does Not Cover

This assessment checks that you can read, write, and debug a basic CNC mill or lathe program on a FANUC/Haas-style control. It covers coordinate systems, G/M codes, tool and work offsets, canned cycles, subprograms, and program verification. It does not cover 5-axis kinematics, macro programming beyond simple variables, probing cycles, or a specific machine's alarm list. Those are separate modules. If you can pass this assessment, you are ready to shadow a real setup and run first articles under supervision.

Every question has one intended answer, but real CNC work is sometimes ambiguous. If you think a question is ambiguous, write down your reasoning — partial credit is given for sound reasoning even when the chosen answer differs from the key. The point is not to memorize a number; it is to be able to explain why a program crashes and how to fix it.

How to Use This Assessment

Take the assessment closed-book the first time. Do not look back at the lessons until you have written down a best guess for every question — even if the guess is "I don't know." Marking a question as "I don't know" is a valid answer and tells you which lesson to reread. After scoring, list every wrong answer by its lesson number and redo that lesson before retrying. A second attempt should score 90 or higher on the items you previously missed; if it does not, the gap is conceptual, not a one-off mistake.

The code-review exercises are not quizzes: they ask you to read a short, deliberately flawed program and list every defect. Treat this like a real first-article check: work top to bottom, confirm the startup block, confirm tool-length and work-offset establishment, confirm the first cutting motion, and watch for modal leakage. A wrong answer that says "it looks fine" on a program that crashes the table is worth zero points.

Retake Policy

You may retake the assessment as many times as you need. Between attempts, reread the specific lessons your wrong answers point to — do not reread the whole course from scratch. After two failed attempts on the same question type, stop and write the program out by hand on paper, then compare it to the worked example in that lesson. A third attempt that still misses the same concept means the lesson itself needs revision; flag it so the course can be improved.

Grading

This assessment is worth 100 points, weighted by task type:

  • 20 basic knowledge questions × 2 points = 40 points (Parts 1–3: recall, code reading, find-the-error).
  • 2 code-review exercises × 10 points = 20 points (Part 4, Q17–Q18: list every defect, then fix; partial credit per defect).
  • 2 final projects × 20 points = 40 points (process plan + coordinates + program + verification; scored on completeness, safety, and geometry).

A passing score requires both (a) total score ≥ 80/100 and (b) every critical safety or geometry error (wrong work offset direction, missing tool-length call before Z-down, G41/G42 reversed into stock, unsafe retract) has been correctly identified and fixed. A score of 98 with an unfixed critical error does NOT pass; you must identify and fix all critical errors, then resubmit.

If you score below 80, identify which lesson the wrong answers cluster around and redo that lesson before retaking. Do not memorize answers; the point is to be able to read and debug code on a real machine.

Code-review exercises: for each, list every error you can find, then fix it. Projects: write the process plan, the coordinates, the program, and the verification steps. Submit them to a more experienced programmer for review before running them on a real machine.

P1 (20 points) — Milling Project

Given a 100×80×20 mm aluminum block, write a complete process plan and program: face mill the top, rough and finish a 60×40 pocket 8 mm deep, drill four Ø6 holes at the pocket corners. Score: process plan 4, coordinates 4, startup/safety 4, toolpath 4, verification plan 4.

Acceptance

G54 at top-left corner; G43 H offsets before Z; G80 after cycles; coolant on; Z50 retract; first-part dry run listed.

P2 (20 points) — Turning Project

Given a raw Ø60 × 100 mm mild-steel bar, write a complete process plan and program: face, rough turn to Ø40 over 50 mm with 0.4 mm diameter finish stock, finish turn, chamfer. Score: setup/chuck 4, rough/finish split 4, startup G18/G97/G99 4, coordinates/diameter 4, verification 4.

Acceptance

G18 plane, diameter programming, G97 constant RPM, G99 feed per rev, tool tip radius accounted for, parts-off listed.
