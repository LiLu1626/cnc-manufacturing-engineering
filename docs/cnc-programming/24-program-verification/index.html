Program Verification Before Cutting

Writing a program is not the same as proving it safe. Verification is layered: each layer catches different errors. No single layer proves everything.

Level: KeyMachine: Mill & Lathe
What you will learn:
  • Simulation: virtual tool path
  • Dry run: real motion at rapid/feed override
  • Single block: one line at a time
  • First-part inspection: measure the actual part

Concept

Verification happens in layers. Simulation (CAM or controller graphics) shows the tool path virtually. Dry run runs the program on the real machine with no tool (or tool at raised Z) at rapid/feed override. Single block executes one line per cycle start. First-part runs the real cut at reduced feed, then measures.

Why It Matters

Dry run at raised Z does NOT prove no collision. With the tool 50 mm above the part, you verify X/Y positioning, but the tool holder, spindle nose, and fixture heights are not tested. A collision between tool holder and vise at Z=-10 will not appear when Z is raised. Dry run catches positioning errors, not 3D interference. Controller simulation with full tool geometry (holder included), or a documented clearance check, is the way to verify 3D interference — raised-Z dry run is not sufficient.

How

Verification layers

  1. Syntax review: read every line; check G90/G91, H/D numbers, units.
  2. Coordinate review: compare programmed coordinates to the drawing.
  3. Simulation: run controller graphics; look for gouges and wrong Z.
  4. Dry run: tool at raised Z, reduced rapid override, observe X/Y motion. Does NOT prove Z or holder clearance.
  5. Single block: step through the first several blocks at controlled feed, verifying each move against the drawing.
  6. First cut: start in air above the part, then engage at a reduced feed override consistent with the operation and your machine's procedure. For tapping or rigid tapping, use the machine's required synchronous feed — do not override feed on those operations.
  7. Inspection: measure first part before continuing production.

Example

A pocket program: simulation shows the tool path. Dry run at Z50 shows X/Y follows the pocket rectangle. But the 100 mm tool holder might hit the 80 mm vise jaw at Z=-5 — dry run at raised Z does not reveal this. Checking holder geometry vs vise height (in simulation or by measurement) is what reveals this interference.

Common Mistakes

  • Thinking raised-Z dry run proves no collision — it does not.
  • Skipping single block because simulation looked fine.
    • li>Running at 100% feed on the first part.

Practice

1. Dry run at Z50 shows no issues. Is it safe to cut?

Show answer

No. It proves X/Y positions are correct, but Z clearance between holder/fixture is untested. Verify holder geometry separately.

2. What does simulation catch that dry run cannot?

Show answer

Tool path gouges, wrong Z depths, and (with full holder model) 3D interference.
