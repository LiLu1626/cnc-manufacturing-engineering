Diagnosing Program Problems

When the machine does something unexpected, systematic diagnosis beats trial and error. This page covers common symptoms and where to look.

Concept

Program problems fall into categories: motion errors (tool goes where it shouldn't), dimension errors (part size wrong), alarm errors (machine stops with a fault), and surface errors (finish is poor). Each has a diagnostic path.

Why It Matters

The #1 debugging mistake is changing a random line and re-running. This compounds errors. Systematic diagnosis: read the alarm, check the relevant modal state, verify coordinates on paper, then make one change.

How It Works

Example

Symptom: hole appears at X50 when program says X30. Diagnosis: (1) Is G90 active? (2) Is G54 X offset correct? (3) Is there a G55 active by mistake? (4) Is the program actually the file you think it is? Check the O number on the controller.

Common Mistakes

  • Guessing and re-running — make one change at a time, observe, then continue.
  • Ignoring the alarm text — the alarm number and message usually point directly to the problem.
  • Changing offsets before checking program — if the program says X30 and the hole is at X50, the offset is off by 20 — fix the offset, don't change the program.

Practice

1. Part is 25.4x too small. What happened?

Ans

Program in mm but machine set to G20 inch, or vice versa.

2. After drilling, the next X/Y move drills a hole unexpectedly. Why?

Ans

Missing G80. The drilling cycle stayed modal.

3. How do you verify which program is loaded?

Ans

Check the O number on the controller display. Machine shops have many programs with similar names.
