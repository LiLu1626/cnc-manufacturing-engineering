Diagnosing Program Problems

When the machine does something unexpected, systematic diagnosis beats trial and error. This page covers common symptoms, where to look, and how to fix each category of programming error without compounding the problem.

Concept

Program problems fall into four categories: motion errors (tool goes where it should not), dimension errors (part size is wrong), alarm errors (machine stops with a fault), and surface errors (finish or tool condition is poor). Each category has a diagnostic path: read the alarm, check the modal state, verify coordinates on paper, then make one change and observe.

Why It Matters

The #1 debugging mistake is changing a random line and re-running. This compounds errors: you fix one symptom but break another, and you lose track of what actually caused the problem. Systematic diagnosis — read, check one thing at a time, change one variable — is the engineering habit that prevents crashes and scrap.

Diagnosis Procedure

  1. Read the alarm — the alarm number and message tell you what the controller thinks is wrong. Do not clear it before reading it.
  2. Check modal state — on the controller, display active G codes. Is G90 or G91 active? G20 or G21? G41 or G40? G80 or a cycle?
  3. Verify on paper — trace the program from the start. Where should the tool be at each line? Compare to where it actually is.
  4. Make one change — fix one thing, then run again. Do not change three lines at once.
  5. Observe — use single-block mode and dry run to watch the corrected motion before full cut.

Example

Scenario: A hole appears at X50 when the program says X30. Systematic diagnosis:

  1. Is G90 (absolute) active? Check the modal display. If G91 (incremental) is active, X30 means "move 30 mm from current position," not "go to X30."
  2. Is G54 correct? Check the work offset display. If G54 X is set to 20, then X30 in the program lands at physical X50.
  3. Is the machine accidentally on G55? Check which work offset is active. If G55 has a different X origin, all positions shift.
  4. Are you running the correct program? Check the O number on the controller display. Machine shops have dozens of similar programs.

Most likely: G54 X offset is off by 20 mm. Fix the offset — do not change the program. If you changed X30 to X10 to compensate, the program is now wrong for the next setup.

Unexpected Tool Motion

If the tool moves where you did not expect, suspect modal state: leftover G91, active G81, wrong plane G18/G19, or inherited G41/G42. Check the modal display on the controller, not just the current line.

Wrong Direction or Wrong Coordinates

A part cut on the wrong side usually means G90/G91 confusion, wrong work offset (G54 vs G55), or mirrored axes. Re-measure, re-check offsets, and verify the part zero matches the drawing datum.

Tool Wear and Surface Finish

Poor finish, chatter marks, or dimensional drift all point to tool wear or rigidity. Replace the insert, check overhang, and confirm the workholding before blaming the program.

Chatter and Vibration

Chatter leaves a wave pattern on the surface. Causes include tool overhang, weak workholding, spindle speed near resonance, or worn inserts. Reduce overhang, increase rigidity, and change speed before changing feed.

Dimensional Drift

If parts start on-size and drift over a shift, suspect thermal growth, tool wear, or workholding loosening. Warm up the spindle, re-check offsets, and monitor temperature.

Chip Control Problems

Long birds' nests wrap around the tool or part. Adjust feed and speed, use a chip breaker geometry, or add pecking. Chips that do not evacuate scratch the finish and can break the tool.

Alarm Codes

Treat alarm codes as clues, not as instructions. Look up the code in the machine manual, understand the condition, and clear it. Resetting repeatedly without understanding damages the machine and the part.

Separating Program Errors from Setup Errors

A part dimension that is consistently off by the same amount points to an offset error. A dimension that varies between parts points to workholding, tool wear, or thermal growth. A move that goes the wrong way points to a program or modal error. Diagnose the pattern before changing code.

Wrong Tool Offset Sign

If a bore cuts too small on the inside or too deep on the outside, the offset sign may be reversed relative to the controller. Re-check the H/D value against the touch-off procedure on this specific machine.

Wrong Cutter Compensation Side

G41 on the wrong side gouges the part. Look at the tool relative to the programmed contour: are you climbing or conventional? Re-read the lead-in move and reverse G41/G42 if needed.

Feed or Speed Alarm

A spindle overload alarm means the cut is too heavy for the tool or machine. Reduce depth of cut, feed, or speed; do not reset and run the same cut again.

Overtravel Alarm

Overtravel usually means the program moves beyond the machine envelope, or G54 is set wrong. Home the machine, re-check work offset, and verify the program does not expect coordinates outside travel.

Surface Finish Worse Than Expected

Compare to tool condition, nose radius, feed per rev, and buildup. A worn insert or built-up edge leaves a smeared surface, not a dimensional error.

Part Not Where the Drawing Says

If the finished part is offset in X or Y, the work zero is wrong, not the program. Re-touch the datum. Do not "fix" it by editing every coordinate in the program.

Bolt Hole Circle Out of Position

If a bolt circle is rotated or shifted, the center coordinate or work zero is off. Re-measure the center from the datums. Do not rotate individual holes.

Bore Size Wrong

A bore that is too small means the boring bar offset needs a radial tweak; too large means it already cut past target. Confirm the target diameter before touching the offset.

Thread Not Accepting the Gauge

If the GO does not enter, check depth, pitch, and spindle/feed sync. If NO-GO enters, material is already removed and the part is likely scrap.

Program Crashes on a Move That Was Fine Before

Something in the setup changed: a clamp moved, a tool got longer, or a different stock was loaded. Re-verify the changed variable, not the whole program.

Establishing a Diagnostic Habit

Write down the symptom, the suspected cause, and the actual fix after every issue. Over time this becomes the shop's troubleshooting knowledge base. Same symptom next month is no longer a mystery.

Tool Breakage

When a tool breaks, stop, inspect, and replace. Do not try to continue with a broken tool — it will wreck the part and possibly the spindle. Note the cut conditions that caused it and reduce them on the next run.

Dimensional Error That Changes Over Time

If parts drift gradually, suspect tool wear or thermal growth. Record dimensions over a batch and re-offset when drift crosses a threshold.

Surface Integrity Issues

Burn marks, white layer, or work hardening indicate the cut was too slow or too heavy. Adjust speed and feed rather than forcing the tool to rub.

Machine-Related Issues

Not every issue is a program bug. Loose belts, worn ballscrews, or faulty encoders cause real machine errors. If symptoms repeat across programs on the same machine, investigate the machine, not the code.

When to Escalate

If a symptom repeats despite three plausible fixes, stop and ask for help. Continuing to tweak without a theory wastes material and tooling. Bring the symptom history to a more experienced operator or the maintenance department.

Using Data to Troubleshoot

Record dimensions across parts. A trend line tells you wear; a sudden outlier tells you a setup error. Numbers beat intuition on the shop floor.

When to Stop the Batch

If one part is out of spec, stop and find the cause before running more. Do not hope the next one will be fine. Scrap piles grow from ignored outliers.

Root Cause, Not Symptom

If the bore is small, adjusting the offset treats the symptom. Find out why the bore went small: tool wear? Deflection? Thermal? Fix the root cause, then adjust offset.

Documentation of Every Fix

Write down what worked. A troubleshooting fix that only lives in your head is lost when you are not at the machine. Keep a simple log on the setup sheet or in the program comments.

Common False Leads

The most obvious cause is often not the real one. Before editing the program, check the simple things: clamp tight? tool seated? offset correct? Most "program bugs" are setup errors.

Building a Troubleshooting Mindset

Every crash is a lesson. What assumption turned out to be wrong? Write it down. Over time you will recognize patterns before they become crashes.

Working with Maintenance

When the machine itself is suspect, describe symptoms precisely: alarm numbers, repeatability, sounds, dimensions. Maintenance can act on data, not on "it feels wrong."

Sharing What You Learned

Tell the next operator about the issue. A problem fixed in isolation repeats on the next shift. Communication on the shop floor prevents repeat scrap.

Common Mistakes

  • Guessing and re-running — change one thing at a time. Multiple changes at once make it impossible to know what fixed it.
  • Ignoring the alarm text — the alarm number usually points directly to the problem. Read it before clearing.
  • Changing the program instead of the offset — if the program says X30 and the hole is at X50, fix G54, not the program.
  • Running full speed for diagnosis — use single-block, dry run, and feed override at 25% when testing.
  • Forgetting to check which program is loaded — O1001 and O1011 can be confused at a glance.

Practice

1. The part comes out 25.4× too small. What happened?

Ans

Units mismatch: the program uses mm (G21) but the machine is in inch mode (G20), or vice versa. 1 inch = 25.4 mm. Check the active units modal.

2. After drilling four holes, the next X/Y move makes an unexpected hole. Why?

Ans

Missing G80 after the hole pattern. The drilling cycle stayed modal, so the next X/Y position triggered another drill cycle. Add G80.

3. How do you verify which program is loaded on the controller?

Ans

Check the O number on the controller display. Machine shops have many programs with similar names; always confirm the O number before running.

4. An arc comes out lopsided. What is the most likely cause?

Ans

I/J center offset error. I/J are incremental from the arc start point, not absolute from G54. Check that I and J are the vector from start to center.
