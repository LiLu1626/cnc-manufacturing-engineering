Modal State and Code Persistence

Modal codes are one of the most important and least understood concepts in G-code. This page explains what modal means, how modal groups work, why forgetting G80 drills unexpected holes, and how to track machine state block by block.

Concept

A modal code stays active after it is commanded. Once G01 is on, every motion block remains G01 until G00, G02, or G03 replaces it. A non-modal code (like G53 or G04 dwell) is active for one block only and does not persist.

Modal codes are organized into groups. Within a group, only one code can be active at a time. Motion codes (G00/G01/G02/G03) are one group. Plane selection (G17/G18/G19) is another. Units (G20/G21) is another. Setting a new code in the same group cancels the previous one automatically. Codes from different groups coexist — G01 does not cancel G21, and G81 does not cancel G90.

Why It Matters

Missing one line — like forgetting G80 after a drilling cycle — means the cycle stays active on the next X/Y move. This is how programs drill holes at unexpected positions. Modal state errors are silent: the code looks fine, but the machine executes a different mode than you intended. Understanding modal groups is how you predict what the machine will do, not just what each line says.

When you read a program, you are not just reading each line in isolation — you are tracking a state machine. After the startup block, the controller is in a specific combination of modes. Each line may change one or more of those modes, and the next line inherits everything the previous line set. A programmer who does not track this will be surprised when a hole appears where none was programmed.

Exact group membership and power-up defaults depend on the controller and on machine settings. The table above reflects typical FANUC/Haas behavior; your controller may differ. When in doubt, the startup block explicitly sets the modes you care about rather than relying on defaults.

How It Works — Example

G01 X10 F200
X50        (still G01, still F200 — no need to repeat)
Y30        (still G01, still F200)
G00 X0 Y0  (now rapid — G01 cancelled by G00)

Lines 2 and 3 inherit G01 and F200 from line 1. If the second line had been intended as rapid, you must explicitly write G00. The machine does not reset to G00 after each block.

Now a more dangerous example:

G81 R2. Z-15. F100.
X10 Y10    (drills hole at 10,10)
X50 Y10    (drills hole at 50,10 — G81 still active)
X50 Y50    (drills hole at 50,50 — G81 still active)
G00 X0 Y0  (PROBLEM: G00 cancels cycle motion on Haas,
            but on some controls G81 stays active and
            this line drills at 0,0 — always write G80!)
G80        (explicitly cancels the drilling cycle)

The safe habit is to always write G80 after the last hole, never rely on G00 or G01 to cancel the cycle. Different controllers handle the boundary differently, and your program should not depend on which one you happen to be running.

The Startup Block as State Reset

This is why every program starts with: G21 G17 G90 G40 G49 G80. It explicitly resets every modal group to a known default, wiping out any leftover state from the previous program. Without this, a leftover G83 peck drill from the previous job could activate on your first X/Y move.

The startup block does not just set defaults — it is a contract between you and the machine. You are saying: "Before I touch any tool, I want metric units, the XY plane, absolute coordinates, no cutter compensation, no tool length compensation, and no drilling cycle active." If the machine was left in inch mode, on the XZ plane, with cutter compensation on, or with a tapping cycle active from the previous job, this block clears all of it. It costs nothing to write and prevents entire categories of crashes.

Modal vs Non-Modal: A Quick Reference

TypeExamplesBehavior
ModalG00, G01, G02, G17, G21, G90, G54, G81, F, S, TPersist until replaced by a code in the same group
Non-modal (one-shot)G04 dwell, G53, G28, G60 exact stopActive for the block they appear in only

Feed F and spindle S are also modal. Once you set F300, subsequent cutting moves inherit it until you change F. This is why you only need to write F on the first cutting move after a rapid, and why you should be deliberate about setting a new feed when the cut type changes.

Tracking State While Reading

A practical habit: when reading an unfamiliar program, keep a mental (or written) table of the current mode after each block. After the startup block, you know G21/G17/G90/G40/G49/G80 are active. After T01 M06, tool 1 is in the spindle. After S2000 M03, the spindle is at 2000 RPM CW. After G43 H01 Z50, tool length offset H01 is active. Every time the program touches a modal group, update the table. When you hit an unexpected move, the table tells you which mode you actually inherited.

Common Mistakes

  • Forgetting G80 after drilling — the cycle continues on the next X/Y move, drilling an unexpected hole.
  • Assuming G01 resets each line — it does not. Modal persists until replaced.
  • Forgetting G40 after cutter compensation — the offset stays active and affects the next contour.
  • Mixing G90/G91 without tracking — switching modes mid-program without resetting causes coordinate errors.
  • Repeating unnecessary codes — while harmless, repeating G01 on every line clutters the program. Modal codes exist to save typing.
  • Assuming G00 cancels a drilling cycle — on many controls it does, but on others the cycle stays modal. Always write G80 explicitly.
  • Leaving G96 CSS active on a lathe when you switch to a finishing tool — CSS is modal and will change RPM as the diameter changes; if you expected a fixed RPM, the surface speed will surprise you.

Practice

1. After G81 R2. Z-15. F100, you write X30 Y20. What happens?

Show answer

The machine moves to (30,20) and drills another hole at R2 Z-15 F100. G81 is modal. You need G80 to cancel the cycle.

2. What cancels G41/G42?

Show answer

G40 cancels cutter compensation. It must be explicitly programmed — the machine does not turn it off automatically.

3. Why is the startup block important?

Show answer

It resets all modal groups to known defaults (metric, XY plane, absolute, comp off, cycles off), preventing leftover state from the previous program from causing unexpected motion.

4. After G01 X50 F200, you write Y30. What mode and feed are active?

Show answer

G01 at F200 — both are modal and inherited. Y30 moves to Y30 in a straight line at 200 mm/min.

5. You see G90 G54 G00 X0 Y0 on one line. Which modal groups are explicitly set on this line?

Show answer

Distance mode (G90), work offset (G54), and motion (G00). Units, plane, compensation, and cycles are inherited from earlier in the program — you must read earlier lines to know them.
