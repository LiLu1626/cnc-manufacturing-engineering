Program Verification

Writing a program is not the same as proving it safe. Verification is layered — each layer catches different errors. No single step proves everything.

What you will learn:
  • Simulation vs dry run vs single block
  • Why raised-Z dry run does not prove 3D clearance
  • What to check on the first part
  • What verification does and does not cover

Layers of Verification

  1. Syntax review: read the program line by line.
  2. Simulation: verify tool path in CAM or controller graphics, with holder geometry.
  3. Dry run: tool at raised Z, reduced rapid, observe X/Y motion. Does NOT prove Z or holder clearance.
  4. Single block: step through first moves at controlled feed.
  5. First cut: start in air, then engage at reduced feed appropriate to the operation. Do not override feed on tapping or synchronous operations.

What Verification Does Not Prove

A raised-Z dry run shows X/Y positioning but does not test whether the tool holder clears the vise, the chuck, or the fixture. Only simulation with full holder geometry, or a documented physical clearance check, reveals 3D interference.

Common Mistakes

  • Thinking dry run at raised Z proves no collision.
  • Running at 100% feed on the first part.
  • Skipping simulation and going straight to single block on a complex part.

Practice

1. Dry run at Z50 looks fine. Is it safe to cut?

Show answer

No. X/Y positions are verified, but Z clearance between holder and fixture is untested. Check holder geometry separately.

2. What does simulation catch that dry run cannot?

Show answer

Tool path gouges, wrong Z depths, and (with holder model) 3D interference with fixtures.
