What Is CNC Programming?

CNC programming is the bridge between an engineering drawing and a moving machine tool. This page explains what a program actually controls and how code becomes metal chips.

Level: BeginnerMachine: Mill & Lathe concept
What you will learn:
  • What a CNC program controls
  • The drawing-to-part workflow
  • Manual programming vs CAM
  • Why coordinates matter before code

Concept

A CNC (Computer Numerical Control) program is a text file of instructions that tells a machine tool where to move the spindle or tool, how fast to spin, and how fast to feed. It does not "think" — it executes one block at a time. The controller reads each line, interprets the codes, and commands the servo motors.

A CNC program (the G-code file) is not the same as a CAM project file. The CAM file holds your model, toolpaths, and setup; the exported NC file is the plain code the machine actually runs.

Why It Matters

Imagine a 60 × 40 mm plate with two holes at (10,10) and (50,30). On a manual mill you would crank the handles, look at dials, and drill. In CNC, you write coordinates. The machine repeats them every time. If the coordinates are wrong, every hole is wrong — consistently. That is why understanding coordinates before code is essential.

How: The Workflow

The path from drawing to part has six stages:

  1. Engineering drawing — dimensions, tolerances, material.
  2. Process planning — roughing vs finishing, tool selection, setup.
  3. Workholding & tooling — vise, chuck, fixtures, cutting tools.
  4. CNC program — coordinates, speeds, feeds, cycles.
  5. Verification — backplot, dry run, single block.
  6. First part — inspect, measure, adjust offsets.

Manual programming suits simple geometries: straight turns, rectangular pockets, hole patterns. CAM programming suits complex 3D surfaces, molds, and aerospace parts. Even with CAM, you must understand the output to check it.

Example

Two holes on a plate. Hole A at (10,10), hole B at (50,30). In plain language: "move to X10 Y10, drill; move to X50 Y30, drill."

G00 X10. Y10.   (position over hole A)
G81 Z-15. R5. F100.  (drill cycle)
G00 X50. Y30.  (next hole, cycle stays active)
G80             (cancel cycle)

Here X50 Y30 is a destination, not a distance from the last move (we use G90 absolute). S2000 sets spindle speed in RPM, not surface speed. F200 is feed rate in mm/min under G94.

Common Mistakes

  • Treating coordinates as distances (absolute vs incremental).
  • Assuming S (RPM) is the same as cutting speed (m/min).
  • Believing CAM output needs no review — wrong posts and unmodeled fixtures cause crashes.

Practice

1. Two holes: A at (10,10), B at (50,30). What is the delta X and delta Y between them?

Show answer

Delta X = 50 − 10 = 40 mm. Delta Y = 30 − 10 = 20 mm. The diagonal distance is √(40² + 20²) = √2000 ≈ 44.7 mm.

2. For a simple stepped shaft vs a complex turbine blade, which would you program by hand and which in CAM?

Show answer

The stepped shaft is straight turns — hand code is efficient. The turbine blade has 3D curved surfaces requiring CAM to generate the toolpath.

3. Why is checking CAM output necessary even if the screen looks correct?

Show answer

Post-processors can output wrong G-codes for your specific machine, and CAM simulation often omits the vise, fixture, or tool holder. You must verify the actual NC code and machine envelope.
