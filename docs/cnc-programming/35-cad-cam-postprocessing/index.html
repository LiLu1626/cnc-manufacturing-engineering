CAD, CAM & Post-Processing

Most production programs start in CAM software. This page explains the CAD → CAM → post-processor → G-code chain and where things go wrong.

Concept

CAD creates the part geometry. CAM generates tool paths on that geometry. Post-processor translates tool paths into machine-specific G-code. Each step introduces potential errors.

Why It Matters

Operators who trust CAM output without review are the ones who crash machines. The post-processor only knows what you told it about the machine. If the toolholder isn't modeled, the CAM doesn't see the collision. If the work offset is wrong, CAM faithfully produces wrong coordinates.

How It Works

The Workflow

  1. Import CAD model into CAM
  2. Define stock, fixtures, datums
  3. Assign tools, speeds, feeds
  4. Generate tool paths
  5. Simulate in CAM
  6. Post-process for specific machine
  7. Review G-code on controller
  8. First part verification

Example

CAM says the program looks perfect. You still must: verify G54 offset, verify H tool lengths, verify tool numbers match the physical carousel, verify the post-processor is correct for your machine.

Common Mistakes

  • Not modeling the toolholder — CAM sees the tip, not the holder. Collisions happen with holders.
  • Wrong post-processor — Haas post on a FANUC machine produces wrong cycle syntax.
  • Ignoring machine envelope — CAM doesn't know the machine's X/Y/Z limits.

Practice

1. What does a post-processor do?

Ans

Translates generic CAM tool paths into machine-specific G-code.

2. Why model the toolholder?

Ans

So CAM simulation detects holder collisions with fixture or part.

3. Does CAM simulation replace machine dry run?

Ans

No. CAM doesn't know your actual G54, H offsets, or tool positions. Dry run on the machine is still required.
