Macro Programming Introduction

Macros add variables, logic, and loops to G-code. This page teaches N-label branching, input validation (including integer checks), and safe arithmetic.

Level: AdvancedMachine: Mill
What you will learn:
  • Variables #1–#33 (local) and #100+ (common)
  • IF/GOTO and WHILE/DO branching with N labels
  • Input validation: reject zero, negatives, and non-integers
  • Divide-by-zero protection

Concept

A macro is a program with variables and logic. Variables like #1, #2 hold numbers. Conditional branching uses IF[condition] GOTO n, where n is a number that matches an N label in the same program. The syntax is GOTO 100 (jump to the block marked N100) — you do not write GOTO N100 with the N in the GOTO statement.

Why It Matters

Branching within a program uses N labels. An O-number identifies a separate program (called by M98); GOTO never references an O-number. If you write GOTO 1000 but no block in the program is marked N1000, the controller cannot find the target — it is not "calling O1000," it is simply missing a label.

Branching Syntax

IF[#1 LE 0] GOTO 100   (jump to N100 if #1 is zero or negative)
WHILE[#3 LT #2] DO 1  (loop while #3 < #2)
...
END 1                   (end of loop body)
...
N100 (ERROR HANDLER)
#3000 = 1 (BAD INPUT)
M30

Worked Example: Bolt-Circle Drill Macro

Input #1 = circle radius. Input #2 = number of holes. This example assumes the program already established: G21, G17, G90, G54, spindle on, coolant on, tool at initial plane. The macro drills holes around a circle centered at G54 X0 Y0.

O3600 (BOLT CIRCLE DRILL MACRO)
#1 = 20.                  (radius, PCD 40 / 2)
#2 = 4                    (number of holes)
#3 = 0                    (hole counter)
(input validation)
IF[#1 LE 0] GOTO 100      (radius must be positive)
IF[#2 LT 3] GOTO 100      (at least 3 holes)
IF[#2 GT 12] GOTO 100     (at most 12 holes)
IF[FIX[#2] NE #2] GOTO 100  (#2 must be an integer)
WHILE[#3 LT #2] DO 1
#4 = 360 * #3 / #2        (angle in degrees)
#5 = #1 * COS[#4]
#6 = #1 * SIN[#4]
G90 G81 X#5 Y#6 R2. Z-10. F100.
#3 = #3 + 1
END 1
G80
M30
N100 (ERROR HANDLER)
#3000 = 1 (BAD INPUT — CHECK RADIUS AND HOLE COUNT)
M30

With #1=20, #2=4: hole angles are 0°, 90°, 180°, 270°. Positions: (20,0), (0,20), (−20,0), (0,−20). The loop runs exactly 4 times.

Integer Validation

The line IF[FIX[#2] NE #2] GOTO 100 rejects non-integer hole counts. Without it, entering #2=3.5 would make the loop condition #3 LT 3.5, executing 4 times (count 0,1,2,3) with angle step 102.857° — not a legal equal-spaced bolt circle. FIX[#2] truncates toward zero; if the truncated value differs from the original, the input was not an integer.

Common Mistakes

  • Writing GOTO N100 — the GOTO statement takes a bare number (GOTO 100); the N prefix only appears on the label block.
  • Using an O-number as a GOTO target — GOTO stays in the current program; O-numbers are separate programs called by M98.
  • Not validating that #2 is an integer — 3.5 holes is not a valid bolt circle.
  • Dividing by an input that could be zero without a guard clause.
  • Forgetting that trig functions use degrees, not radians, on Haas/FANUC.

Practice

1. What happens if someone sets #2 = 3.5?

Show answer

The integer check IF[FIX[3.5] NE 3.5] is true (FIX[3.5]=3, 3≠3.5), so the program jumps to N100 and alarms. Without this check, the loop would run 4 times at 102.857° spacing.

2. What is the correct syntax to jump to the block marked N200?

Show answer

GOTO 200 — bare number, no N prefix in the GOTO statement. The N200 appears on the target block itself.

3. Why is radius validation needed before the WHILE loop?

Show answer

Radius enters the COS/SIN calculations. A zero or negative radius produces wrong (or mirrored) hole positions. The guard clause catches it before any motion.
